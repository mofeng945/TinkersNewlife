# 巫师套装底图修改指南（`grey.png` / 自绘模型贴图）

> 你问的是"想自己改底图该怎么做"。结论先说：**改明暗/花纹随便改，改位置要连 Java 一起改**，
> 改完必须**同步 5 张底图 + 重新构建部署**。下面按这个顺序讲清楚。

---

## 0. 五步速查

```powershell
# 1) 用画图软件打开并修改（唯一"正本"是 grey.png）
#    src\main\resources\assets\tinkersnewlife\textures\armor\wizard\grey.png
#    128x128、PNG、带透明通道

# 2) 同步到另外 4 张（否则帽/袍/护腿/靴子会不一致）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\sync-wizard-base-textures.ps1

# 3) 看图/查表（哪个像素属于哪个方块的哪个面）

# 4) 构建（底图不用编译，但要走一遍流程确认没漏文件）
.\gradlew build

# 5) 关掉游戏后部署到两个整合包实例
powershell -NoProfile -ExecutionPolicy Bypass -File tools\deploy.ps1
```

## 1. 这张底图为什么长这样

巫师套装是**自绘 Java 模型**（`client/model/WizardArmorModel.java`），贴图不是"一整张皮肤图"，
而是当**每面光照灰阶图**用：

1. 模型里每个方块给一个 `texOffs(u, v)`（`addBox(...)` 的最后两个参数）；
2. Minecraft 按**标准盒式 UV 布局**去这张图上取六个面：

   | 面 | 取图位置（左上角） | 尺寸 |
   |----|------------------|------|
   | up（顶） | `(u+d, v)` | `w×d` |
   | down（底） | `(u+d+w, v)` | `w×d` |
   | east（-X 侧） | `(u, v+d)` | `d×h` |
   | north（-Z 前） | `(u+d, v+d)` | `w×h` |
   | west（+X 侧） | `(u+d+w, v+d)` | `d×h` |
   | south（+Z 后） | `(u+d+w+d, v+d)` | `w×h` |

   （`w/h/d` 是**换算后**的宽度/高度/厚度＝Blockbench 数值 × `HAT_SCALE`，当前 0.8）

3. 所以底图里每块区域的 `up` 位置画亮灰（≈249）、`down` 画暗灰（≈160）、侧面画中灰（≈179~215），
   帽子看起来才有立体感（实体模型本身**不做**逐面光照）；
4. 图片必须是**灰度**：实际颜色 = 底图亮度 × 材料色（顶点着色）或材料贴图。
   加彩色会与材料色相乘变成脏色 ✗；
5. **透明像素 = 那个面直接不画**（隐形）。这是最容易踩的坑 ✓。

## 4. 三种改法

### 改法 A：只改明暗/花纹（最安全，推荐）

只动**像素颜色**，不动任何区域的位置和大小。可以：

- 整体调亮/调暗某个面（比如想让帽顶更亮、垂布更暗）；
- 在已有区域里画花纹（条纹、缝线、布纹），注意保持灰度；
- 把某些像素改成透明（= 那个面开洞/破布效果）。

改完 → 同步 4 张 → build → deploy，收工。**Java 一行都不用动**。

### 改法 B：挪动区域位置（改 UV）

比如你想把帽身挪到别的空位：

1. 改 `WizardArmorModel.java` 里对应 `addBox(...)` 的 `u, v`；
2. 在底图里把**整个布局矩形**（宽 = `2w+2d`、高 = `h+d`）连同里面六个面的内容一起搬过去；
3. 跑 `tools\wizard-atlas-map.ps1` 核对新位置（编号框选对得上）；
4. 同步 → build → deploy。

⚠ 只改一边（只改 Java 或只改图）⇒ 取到别处的像素，出现**串色/错位/透明洞**。

### 改法 C：加一个新方块

1. 在 Blockbench 里加方块、**放进 `plating` / `maille` / `lace` 三个组之一**，导出 `wizard_head.json` 给我（或自己按下面做）；
2. 按第 1 节的公式把 `from/to` 换成 Java：`x/z = (模型坐标 − 8) × 0.8`，
   `y = −8 − (to.y − 11.04688) × 0.8 + HAT_SINK`，`w/h/d = 差值 × 0.8`；
3. 给它分配一块**自由区**的 `texOffs`（`y ≥ 100`，例如 `(40, 100)` 往后排）；
4. 在底图里按六面公式把这块布局画出来（可以照抄相邻区域的灰值）；
5. 同步 → build → deploy。

> 这一步最容易漏第 4 步：**不画就隐形**。`tools\patch-wizard-hat-atlas.ps1` 就是上次给
> 坠饰（编号 1）和垂布（编号 7）补画区域的脚本，可以照着改成自己的新方块。

## 5. 画图时的注意点

- 尺寸**必须 128×128**（`WizardArmorModel.TEX_W/TEX_H`），PNG + 透明通道；
- 只画**灰度**（R=G=B）。工具里别开"颜色配置文件/ICC"，保存时不要勾选"交错"之类的花活；
- 直线尽量落在**整像素边界**：布局尺寸常带小数（如 `h=0.27`），取整时差一像素并不明显，
  但区域之间**不要重叠**，重叠 = 两个方块互相抢像素；
- 灰阶亮度参考：顶 ≈249、底 ≈156~164、侧面 ≈179~215（这是现成的观感基线）；
  生成器把亮度线性映射到材料色（`k = 0.72 + 亮度/255 × 0.26`，见 `tools/gen-wizard-armor-materials.ps1`），
  所以**别全用 255**，否则各面一样亮、立体感消失；
- 改完一定要**同步 5 张**（第 2 节），否则"头对了、袍子还是旧的"。

## 6. 想让"不同材料有不同花纹"（进阶）

现在的颜色是"底图亮度 × 材料色"。如果某个材料想要专属图案：

- **推荐**：在资源包里放 `assets/tinkersnewlife/textures/armor/wizard/<前缀>_tinkersnewlife_<材料>.png`
  （前缀 = `hat` / `robe` / `mage_leggings` / `mage_boots`；材料 = `origin_alloy`、`hastur_malice` …）。
  渲染层 `WizardArmorTextures.materialArmorTexture(...)` 优先用这种"每材料贴图"，**找到就不再乘材料色** ⇒
  可以画彩图 ✓。命名规则见 `tinkering/generator_part_textures.json`（匠魂生成器也是按这个命名产出）；
- 也可以跑游戏内 `/tconstruct generate_part_textures`，它会以 `hat.png` 等为底图批量产出上面那种文件
  （所以第 2 节的 4 张"槽底图"要和 `grey.png` 保持一致）；
- `tools/gen-wizard-armor-materials.ps1` 产出的 `<材料>.png`（如 `origin_alloy.png`）
  **不是**上面那个命名 ⇒ 当前渲染查表查不到它，只作为备用素材保留。

## 7. 出问题怎么查

| 现象 | 多半原因 |
|------|---------|
| 某块**完全看不见** | 那个区域是透明像素（漏画/画到自由区但没画内容） |
| 颜色**发脏、偏色** | 底图带了彩色（和材料色相乘），或用了不是灰度值 |
| 一块的图案**串到另一块**上 | 区域重叠，或 Java 的 `texOffs` 和图不同步 |
| 只有**头**变了，袍/腿/靴没变 | 忘了同步另外 4 张底图 |
| 六个面**一样亮**、没立体感 | 明暗对比太小（顶应明显比底亮） |
| 改了没反应 | 没重新 build+deploy，或游戏没关（部署脚本会拒绝） |

排查命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\wizard-atlas-map.ps1   # 看区域图 + 表格
powershell -NoProfile -ExecutionPolicy Bypass -File tools\sync-wizard-base-textures.ps1  # 同步 + 校验尺寸
```

## 8. 直接"在 Blockbench 里画"的推荐流程（一键转换 ✓）

你完全可以在之前那个模型上直接画，然后交给我／自己跑一条命令。要点如下。

### 8.1 Blockbench 这边的设置（直接影响清晰度）

| 项 | 建议 | 原因 |
|----|------|------|
| Texture 尺寸 | **128×128**（至少 64×64） | 现在这份导出里 UV 只落在 `0~4.65` 这种很小的空间里 ⇒ 一个面只有几个像素，放大后会糊 ✗ |
| UV 方式 | 每个方块用 **Box UV**（或至少重新 Auto UV 一次） | 六面落在标准布局上，转换无损 ✓ |
| 面的 UV 旋转 | 保持 **0** | 脚本只处理 0 / 180；90/270 会提示你复位 ✓ |
| 分组名 | 必须还是 `plating` / `maille` / `lace`（`lance` 也认 ✓） | 组名 = 材料槽（0/1/2）✓ |
| 颜色 | 想保留"按材料换色"就画**灰度**；想要固定配色就画彩色 ✓ | 彩色会和材料色相乘发脏 ✗（脚本会打印饱和度提示 ✓） |

### 8.2 导出与转换

```powershell
# 导出：File → Export → Java Block/Item（wizard_head.json）+ 贴图 PNG

# 演练（只生成预览，不改任何东西）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\import-hat-blockbench.ps1 `
    -Json "$env:USERPROFILE\Desktop\wizard_head.json" -Texture "$env:USERPROFILE\Desktop\my_hat.png"
#   → build\hat-import-preview.png（新底图预览）+ build\hat-import-preview.java.txt（要写入的 Java 片段）

# 落地
powershell -NoProfile -ExecutionPolicy Bypass -File tools\import-hat-blockbench.ps1 `
    -Json "$env:USERPROFILE\Desktop\wizard_head.json" -Texture "$env:USERPROFILE\Desktop\my_hat.png" -Apply
#   → 重排 grey.png 并同步 4 张 + 替换 WizardArmorModel.java 的两段生成区 ✓
```

脚本做的事：① 读模型里每个方块的大小（×`HAT_SCALE`）；② 自动给每个方块分配一块不重叠的底图区域
（`texOffs`，只占 `x<96`，右边袍/袖/腿/靴区域原样保留 ✓）；③ 把你画的**每个面**按 UV 重采样贴到对应面上；
④ 自动识别"UV 空间 ↔ 贴图像素"的缩放（现在这份是 `uv × 11.95` ✓，因为导出里的 UV 空间很小）；
⑤ 生成 Java（命名 `<组>_<序号>`，如 `plating_3`）替换 `// <<< HAT_ADD_BOX >>>` 与 `// <<< HAT_PARTS >>>` 两段；
⑥ 打印饱和度提示与装箱表。

### 8.3 注意

- **标记之间不要手改**：`WizardArmorModel.java` 里 `HAT_ADD_BOX` / `HAT_PARTS` 两段是生成区，改了几何或贴图请重新跑脚本 ✓；
- 转换后 → `tools\wizard-atlas-map.ps1` 核对区域 → `.\gradlew build` → 关游戏 → `tools\deploy.ps1`；
- 方块**数量随便加**（脚本按你导出的 elements 全量重建 ✓），只要都在三个组里；
- 如果模型里带了**面级 UV 旋转 90/270**，脚本会列出来并跳过那些面 ⇒ 先复位再导出 ✓。
