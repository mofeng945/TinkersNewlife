# 墨默（KtuluMomo）技能开发准则 v1

> 依据：**诡厄巫法·使徒**（`com.Polarice3.Goety.common.entities.boss.Apostle`，2388 行反编译实读）
> ＋ 本仓库 2026-10-15 那一轮踩过的坑。新技能一律按本文件写，**不要**再自创机制。

---

## 0. 一句话总纲

**技能 = 实体自己的状态 ＋ 实体自己的 Goal；客户端只读状态，事件层只做兜底。**
凡是"在外面扫全服实体"、"往玩家身上挂标记"、"清 AI"、"拉坐标"的做法**一律禁止**。

---

## 1. 分层（照使徒的四层，一层都不许跨）

| 层 | 使徒怎么做的（实读） | 我们要写的 |
|---|---|---|
| ① 状态 | `SpellCastingCultist`：`EntityDataAccessor<Byte> SPELL` ＋ `int spellTicks`（存 NBT）；`isSpellcasting()` 客户端读同步字节、服务端读 `spellTicks > 0` | `KtuluMomo` 上：`DATA_SPELL`(Byte)、`DATA_CAST_TICKS`(Int)、`isBusy()` |
| ② 冷却 | `Apostle`：每技能**独立字段** `coolDown/tornadoCoolDown/infernoCoolDown/monolithCoolDown/damnedCoolDown` ＋ `spellCycle`；在 `customServerAiStep` 里 `--`（1525-1536 行） | 每技能独立字段或一张表；**只在实体 tick 里减** |
| ③ 排序 | `goalSelector.addGoal(3, new FireballSpellGoal(this))`（390-392 行）；`SecondPhaseIndicator` 挂在**优先级 1** | 技能＝Goal；优先级 0 浮水/1 转阶段/2 近战/3 技能/4 闲逛 |
| ④ 表现 | `ApostleModel.setupAnim` 只按**阶段**切可见性；施法姿势走 `CultistArmPose`／`getArmPose()`，由**状态**决定 | 模型只读 `DATA_SPELL` 选分支；**不要自己算客户端时钟** |
| ⑤ 血条 | `ModServerBossInfo.update()`：每 tick `setProgress` ＋ **对看不见的玩家补加入包** | 抄它，别等事件 |

## 2. 站定（最容易写错的一条）

使徒的转阶段站定**只有 10 行**：

```java
this.goalSelector.addGoal(1, new SecondPhaseIndicator());   // 355 行
class SecondPhaseIndicator extends Goal {
    public boolean canUse() { return health <= maxHealth / 2 && getTarget() != null; }
    public void start()     { setSettingUpSecond(true); }   // 只置一个标志
}
```

**站定 = 状态标志 ⇒ 其它所有 Goal 的 `canUse()` 返回 false ⇒ 没人给它速度 ⇒ 自然不动。**

✅ 正确做法
- 加一个 `isBusy()`（施法中／转阶段中）。
- **每个**技能 Goal、以及移动类 Goal，`canUse()` 里都判 `!isBusy()`。
- 需要转向就 `getLookControl().setLookAt(target)`。

❌ 禁止（都是我这轮踩过的）
- `setNoAi(true)`：会**粘住**，恢复慢、下线后仍冻结。
- 每 tick 清零 `deltaMovement`：如果写在 `ServerTickEvent.END`，实体**这一 tick 已经走完了**，等于没清。
- 记坐标再 `setPos` 拉回：`putIfAbsent` 会留下**上一次施法的旧坐标**，表现为"一蓄力就被拽回上次的位置"。
- 上面的"定身补丁"曾经叠了四层，全部删除。

## 3. 冷却与排序

- **每个技能一个自己的冷却**：`blinkCool / chordCool / resonanceCool`，互不干扰。
- **递减位置**：实体自己的 `customServerAiStep()` 或 `tick()` 里，`if (cool > 0) --cool;`。
- **排序**：
  - 用 `goalSelector` 的优先级表达"谁优先"；
  - 同级技能之间用 **`spellCycle` 轮转指针**挑一个（学 `Apostle.spellCycle`）；
  - Goal 的 `canUse()` 判 `cool == 0 && !isBusy() && 距离/阶段满足`。
- **一键开关**：把"启用哪些技能"改成"注册哪些 Goal"，不要再写 `static final boolean XXX = true` 满仓库判。
- 阶段化：数值随阶段变（使徒 `isSecondPhase() ? 200 : 400`），阶段本身也是状态位。

---

## 4. 动作与渲染

- **姿势由状态驱动**：模型读 `DATA_SPELL`（0=无、1=瞬身、2=共鸣、3=和弦…）选分支。
- **进度用同步值**（`DATA_CAST_TICKS`），**不要**用客户端时钟——否则"环和判定不同步"。
- ⚠ 模型里**不要**在分支前写 `if (!CHARGING) return;` 这种早退：我就是这么把和弦的抬手吞掉的。
  早退条件必须**覆盖所有会用到后面姿势的技能**。
- 头部/光环这类持续旋转量要么用 `ageInTicks * 小系数`（使徒的 `halo1.yRot = ageInTicks * 0.01F`），
  要么别动；**不要 `yRot += …` 累加**，那会表现为"头一直转圈"。

---

## 5. 血条

- 学 `ModServerBossInfo`：`extends ServerBossEvent`，`update()` 每 tick 改进度，
  **对 `getSensing().hasLineOfSight` 不成立的玩家补 `addPlayer`**。
- `ServerBossEvent#addPlayer` 对"服务端集合里已有"的玩家**不发包**；`setVisible(false)` 后
  `addPlayer` **也不会复位**可视标志。要做"补回来"就必须 `setVisible(true)` ＋ `removePlayer`→`addPlayer`。

---

## 6. 禁改清单（血泪）

1. 不要碰 `content/entity/ktulu/a.java` 的**窗口语义**：它只承认"窗口内拦截"，
   在窗口外硬拦会触发镜像/MAC 自检 → `TP` → 血条被隐藏、保护失效。
   要用就**按它的规矩**：`q2`（问）→ `q3`（记账，会开 `V` 窗口）。
2. `KtuluMomo.hurt` 里判死只能用**镜像**：`isDeadOrDying()` 会被"别的模组直接调 `die()`"污染，
   一旦置 `tnl$dead`，整条保护被闩死（不限伤、无免疫窗）。
3. 注入 `LivingEntity#setHealth` 的正确 SRG 名是 **`m_21153_(F)V`**（不是 `m_5634_`）。
   `getHealth` 是 `m_21223_`，`hurt` 是 `m_6469_`，`die` 是 `m_6667_`。
4. 残影/幽灵绘制：`MultiBufferSource` 包装时**只重定向顶点格式相同的请求**，
   否则 "Not filled all elements of the vertex" 崩溃。
5. 改文件用**按行/按缩进**定位；锚点里带中文或 `\uXXXX` 极易 `ANCHOR MISS`。

## 7. 新技能 Checklist（照抄填空）

```
[ ] 1. 一个 id（Byte）＋ 一句"什么条件触发"
[ ] 2. 三个时长：windUp（前摇）/ cast（持续）/ recover（后摇），各自 tick 数写清楚
[ ] 3. 一个自己的冷却字段（数值 + 从哪一刻开始计：起手还是结束）
[ ] 4. 触发距离区间 [min, max] 与阶段要求
[ ] 5. 写一个 XxxGoal extends Goal：
       canUse()  = 冷却归零 && !momo.isBusy() && 目标/距离/阶段满足
       start()   = setSpell(id, windUp + cast)；记录自己的相位计时；打音效/粒子
       tick()    = 按相位推进；到点进下一相位；结束相位调 stop()
       stop()    = setSpell(0, 0)；本技能冷却 = N；清自己的临时状态
[ ] 6. 注册：goalSelector.addGoal(3, new XxxGoal(this))（优先级想清楚）
[ ] 7. 客户端：KtuluMomoModel 里按 DATA_SPELL 加一个分支（不要早退吞掉）
[ ] 8. 表现：音效（起手/进行/收尾）＋ 粒子，全部服务端发
[ ] 9. 日志：一条 TNLxxxx 起手、一条结束，能一眼看出相位与随机值
[ ] 10. 验证：check-json bad 0 → BUILD SUCCESSFUL → 两包 MD5 一致 → 实机看一遍四个相位
```
