# 匠魂新生 开发备忘录

> 防止遗忘「术式 / 领域 / 咒具制作」三大系统基本流程的速查手册。
> 模组：`com.mofengbaizhi.tinkersnewlife`（MC 1.20.1 Forge 47.x + 匠魂 TConstruct + Mantle + Curios）
> 所有"注册内容"必须在注册表冻结前用 DeferredRegister/RegistryObject 完成，**禁止运行时 `new Item` 注册**。

## 〇、总览：两大内容路线

| 内容类型 | 走匠魂工具链？ | 载体 |
|---|---|---|
| 术式（technique） | 是（占用咒力核心的 technique 槽） | `BaseTechnique` 单例 + 空壳 Trait modifier + crystal 配方 |
| 领域（domain） | 是（占用咒力核心的 domain 槽） | `BaseDomain` 子类 + 空壳 Trait modifier + crystal 配方 |
| 咒具（天逆鉾/杜兰达尔） | **否**（原版剑逻辑） | `CursedToolItem`（SwordItem 子类） |
| 模块化装备（咒力核心/魔杖/悠悠球/飞剑/战镰/驯龙杖/噤默手套） | 是 | `ModifiableItem` + `ToolDefinition` + parts/patterns |
| 强化特性（modifier/trait） | 是 | `StaticModifier` 注册 |

咒力核心（Curse Core）是术式/领域系统的中枢：佩戴在 curios `curse_core` 槽，自带槽位
`domain:1 + technique:1 + defense:2 + upgrades:3`，其 tool_definition 见
`src/main/resources/data/tinkersnewlife/tinkering/tool_definitions/curse_core.json`。

## 一、新增一个术式（technique）

### 概念
- **Technique 单例**（如 `SkyManipulationTechnique.INSTANCE`）：真正的术式逻辑，继承 `BaseTechnique`，构造时 `super(Modifiers.XXX.getId())` 绑定自己的 modifier id。
- **Trait 空壳**（如 `SkyManipulationTrait extends Modifier`）：几乎无逻辑，只是"核心上的术式标记"，让术式能装进咒力核心 technique 槽、被切换/释放。
- 按键流程：`TechniqueHandler` 扫描核心上所有已注册术式 → 玩家切换选中 → 按下/松开/反转(F)调用选中 technique 的钩子（`PacketUseTechnique`/`PacketUseReverseTechnique` → `TechniqueHandler.onKeyPress/onReverseKeyPress...`）。

### 新增步骤（8 步）
1. **写 Trait 空壳** `content/modifier/XxxTrait.java`：
   ```java
   public class XxxTrait extends Modifier { }   // 纯标记，逻辑在 Technique 单例
   ```
2. **在 `content/Modifiers.java` 注册**（照 KaiTrait）：
   ```java
   public static final StaticModifier<XxxTrait> XXX =
       MODIFIERS.register("xxx", XxxTrait::new);
   ```
3. **写 Technique 单例** `content/curse/technique/XxxTechnique.java extends BaseTechnique`：
   ```java
   public final class XxxTechnique extends BaseTechnique {
       public static final XxxTechnique INSTANCE = new XxxTechnique();
       private XxxTechnique() { super(Modifiers.XXX.getId()); }
       // 即时型：覆写 onCast(player, target)
       // 近身限定：覆写 isTargetInRange（如捌 3 格内）
       // 蓄力型（灶·开范式）：onKeyPress 换手蓄力 / onKeyRelease 恢复+发射
       // 蓄力型（苍·赫范式）：状态机 onKeyPress/onKeyRelease，F 反转合成茈
       // 伤害型务必在 onCast 里走 CurseCoreTraitHelper.applyCurseCoreTraits/afterCurseCoreHit
   }
   ```
4. **在 `TinkersNewlife.java` 构造器登记**：`TechniqueHandler.register(XxxTechnique.INSTANCE);`
   → **crystal（镶嵌）/salvage（剥离返还槽）/extract（萃取成水晶）配方与墨默商人货架全部自动派生**，无需另写。
5. **清理与每 tick 驱动（按需）**：蓄力/操控状态挂进 `TechniqueHandler.onPlayerLoggedOut/onPlayerDeath`；每 tick 服务端逻辑挂 `TinkersNewlife.ForgeEvents.onServerTick`。
6. **资源**：
   - 图标 `assets/tinkersnewlife/textures/gui/modifiers/<id>.png`
   - `assets/tinkersnewlife/tinkering/modifier_icons.json` 追加
     `"tinkersnewlife:<id>": "tinkersnewlife:gui/modifiers/<id>"`
   - `assets/tinkersnewlife/lang/zh_cn.json` 三键：`modifier.tinkersnewlife.<id>`（名称）、
     `.flavor`、`.description`（名称键同时用于切换提示与领域标题）
7. **advancement**：`data/tinkersnewlife/advancements/techniques/<id>.json`（`{"criteria":{"unlock":{"trigger":"minecraft:impossible"}}}`）
   + `content/curse/TechniqueAdvancementHandler.java` 静态块
   `put(Modifiers.XXX.getId(), "techniques/<id>")`（照 kai）。
8. **remove_blacklist**：`data/tconstruct/tinkering/tags/modifiers/remove_blacklist.json` 追加
   `"tinkersnewlife:<id>"`（防被普通途径移除，只能走萃取/配方）。

**可选**：加入 `CurseCoreRitualHandler.generateCurseCore` 的术式数组，让生成仪式可随机给到。

### 获取途径（玩家侧）
- **墨默商人**（`MomoMerchant.ensureOffers`）每天随机上架 2 个术式水晶
  （`ModifierCrystalItem.withModifier(techniqueId)`，40-60 格赫罗斯残骸）。
- **咒力核心生成仪式**（`CurseCoreRitualHandler`）产出的核心随机附 1 术式 + 1 领域。
- 用带术式 modifier 的水晶在工匠站给核心"镶嵌"（扣 1 technique 槽）；剥离走萃取返还槽。

### 蓄力/反转样板
- 蓄力换手型：`ZaoKaiTechnique`（灶·开，换 FLAME_ARROW_ITEM 手持蓄力、松手发射）。
- 状态机型：`WuliangCangTechnique`（苍/赫/茈，F 反转键在蓄力中合成茈）。
- 反转语义自定：`SkyManipulationTechnique`、`WuWeiTechnique`、`ReverseCursedTechnique` 等覆写 onReverseKeyPress。

## 二、新增一个领域（domain）

### 概念
- **Domain 子类** `extends BaseDomain`：构造 `(UUID owner, Vec3 center, int radius, double curseCostPerSecond)`，
  center=展开瞬间玩家位置（球心），radius 惯例 = `CursePowerHelper.getCurseOutputLevel(player)*5`，
  消耗惯例 = `radius × 每秒每半径消耗`（坐杀搏徒 ×20、御厨子 ×40、无量空处 ×80）。
- **Trait 空壳** 占 domain 槽（核心固定只有 1 个领域槽）。
- 领域工厂 `static XxxDomain tryCreate(ServerPlayer)`：校验条件，不满足返回 null（已在工厂内提示）。
- 展开后：视觉黑球实体 + 隐形阻挡墙 + 困锁 + 每 tick 消耗/逻辑 + 对抗，全部由 BaseDomain/DomainRegistry 通用外壳接管。

### 新增步骤（7 步）
1. **Trait 空壳** `content/modifier/XxxDomainTrait.java extends Modifier`。
2. **`content/Modifiers.java`** 注册 `StaticModifier`。
3. **领域类** `content/curse/domain/XxxDomain.java extends BaseDomain`：
   - 抽象钩子必实现：`getDomainNameKey()` → `"modifier.tinkersnewlife.<id>"`（展开大标题）；
     `isValid(player)` → 核心上仍有该 modifier（否则领域被破坏+熔断）。
   - 可选覆写：`onOpen` / `onTick(player, serverTickCount)` / `onClose(player, msgKey)` /
     `onClashStart/onClashEnd`。**计时用 `server.getTickCount()`，别用 getGameTime**（踩坑）。
   - 效果实现参考：`FuMoYuChuZiDomain`（AABB 圈选 + CurseCoreTraitHelper 让领域伤害带核心材料特性）。
4. **登记** `TinkersNewlife.java`（150-153 区块）：
   ```java
   DomainRegistry.registerDomain(Modifiers.XXX_DOMAIN.getId(), XxxDomain::tryCreate);
   ```
   → V 键展开、crystal/salvage 配方自动生效，**无其它注册点**。
5. **资源**：图标 png + `modifier_icons.json` + lang 三键（同术式）。
6. **advancement**：`data/tinkersnewlife/advancements/domains/<id>.json` +
   `TechniqueAdvancementHandler` 登记 `put(..., "domains/<id>")`。
7. **remove_blacklist.json** 追加 id。

**可选**：加入 `CurseCoreRitualHandler.generateCurseCore` 的 domains 数组（仪式随机给）。

### 现有领域参考
`ZuoShaBoTuDomain`（坐杀搏徒）、`WuLiangKongChuDomain`（无量空处）、`FuMoYuChuZiDomain`（伏魔御厨子）。
通用设施（新领域无需注册）：阻挡方块 `ModBlocks.DOMAIN_BARRIER`、视觉实体 `ModEntities.DOMAIN_VISUAL`（渲染注册于 `ClientEventHandler`）。

## 三、咒具与模块化装备制作

### 关键区分（勿混）
- **咒具（天逆鉾/狱门疆/杜兰达尔剑）= 原版剑**，`CursedToolItem extends SwordItem`：无限耐久、命中亡灵 +6、
  `ignoresInfinity()` 默认 false（天逆鉾覆写 true 穿无下限）。**不是匠魂工具**。
- **匠魂工具（咒力核心/魔杖/悠悠球/飞剑/战镰/驯龙杖/噤默手套）= `ModifiableItem` + `ToolDefinition`**，走工匠站全流程。
- 术式/领域 modifier 多为**空标记类**，逻辑在 Technique/Domain 单例与事件 Handler。
- 核心**没有自定义 GUI**："装术式/剥离"UI = 匠魂工匠站配方系统（crystal/salvage/extract），不是本模组 Screen。

### A. 新增自定义物品（N 步）
1. `content/item/` 新建 Item 子类（咒具 `extends CursedToolItem`，Tier 匿名类内联）。
2. `content/ModItems.java`：`ITEMS.register("id", () -> new X(new Item.Properties()...))`
   （**注册表冻结：只许在 supplier 里 new**；勿运行时补注册）。
3. 方块物品/药水/实体/声音各进对应 DeferredRegister（ModBlocks/ModEffects/...）。
4. 创造栏：`ModCreativeTabs.displayItems` 里 `output.accept(...)`；
   匠魂工具用 `addAllToolVariants(output, definition, item, partCount)`，部件 `addAllPartVariants`。
5. 资源：`assets/.../models/item/<id>.json` + `textures/item/<id>.png`；lang `item.tinkersnewlife.<id>`（描述 `.desc`）。
6. 行为/掉落：`content/handler/*.java` 事件或 loot modifier（如 `DurandalConversionHandler`）。

### B. 新增匠魂工具（含自带 modifier / 挂核心槽）
1. item 类 `extends ModifiableItem`，静态 `ToolDefinition.create(rl("<tool>"))`；饰品实现 `ICurioItem`。
2. `ModItems` 注册工具 item + 必要 ToolPartItem 部件/铸模铸件。
3. `data/.../tinkering/tool_definitions/<tool>.json`：parts + `modifier_slots` + 自带 `traits`
   （咒力核心：`domain:1 technique:1 defense:2 upgrades:3` + 自带 curse_output/curse_total 1 级）。
   新槽类型需在 `TinkersNewlife()` 构造器 `SlotType.getOrCreate("xxx")`。
4. 部件数据：`tinkering/parts/<part>.json`（stat_type）+ 图标/模型。
5. `tinkering/station_layouts/<tool>.json` 定工匠站 GUI（tool_slot/input_slots）。
6. 配方：`recipes/tools/building/<tool>.json`；多部件还需 parts builder/cast + smeltery/casts 与 casts 标签（模板 dragon_core/yo_yo）。
7. 打标签：`data/tconstruct/tags/items/modifiable/...`（melee/primary、weapon 等）；不可拆解加 `unsalvageable.json`。
8. curios 槽：`ModCurios.enqueueIMC` + `data/curios/tags/items/<slot>.json`；`canEquip` 校验。
9. 特殊添加通道（咒力核心术式/领域）：`recipes/modifiers/crystal/<kind>.json`（crystal_modifier 镶嵌扣槽）
   + `salvage/<kind>.json`（modifier_salvage 剥离退槽）+ 可选 `extract/<kind>.json`（剥离成水晶转移）。
   新增术式/领域**自动被覆盖**（加载时遍历 TechniqueHandler/DomainRegistry）。

### C. 新增仪式配方（多方块脚本式，参考 CurseCoreRitualHandler）
1. `content/curse/ritual/XxxRitualHandler.java`，`@EventBusSubscriber(FORGE)`，
   静态 `Map<BlockPos,RitualData>` 存进行中仪式。
2. 触发：`RightClickBlock`（空手/特定方块）或 ServerTick 扫 ItemEntity。
3. 校验：结构方块计数/偏移硬编码；流体走 `IFluidHandler` capability；必要时月相/亮度/露天。
4. 演出：ServerTick(END) 驱动 `ticksLeft--` + 粒子（光束/BlockParticleOption 连线）。
5. 完成：`handler.drain` 扣流体、`giveExperienceLevels` 扣经验、`addFreshEntity(new ItemEntity(...))`；
   造核心参考 `CurseCoreRitualHandler.generateCurseCore`（ToolStack.from → setMaterials → addModifier
   → `persistentData.addSlots` 扣槽 → createStack）。
6. 结算状态：写玩家 PersistentData（如 `BindingStateHandler`）；提供指令清理（`/tinkersnewlife unbind`）。
7. 中断：死亡/登出 abort；DRAIN/FINAL 阶段 `LivingHurtEvent.setCanceled` 免疫。
8. 文案 `message.*`；手册结构图用 `patchouli:multiblock` 页（参考 entries/ritual.json）。

### D. 新增通用强化特性（modifier，极简）
1. `content/modifier/XxxTrait.java extends Modifier`（纯钩子或空壳 + `content/modifier/events/` 事件 Handler）。
2. `content/Modifiers.java`：`MODIFIERS.register("xxx", XxxTrait::new)`（ModifierDeferredRegister 已挂载，勿重复）。
3. lang `modifier.tinkersnewlife.xxx`；图标 png + `tinkering/modifier_icons.json` 行。
4. 可应用：`recipes/modifiers/xxx.json`（`tconstruct:modifier`）或挂材料特性 `tinkering/materials/traits/<mat>.json`。
5. 约束：`remove_blacklist.json`（禁普通清洗）/ `extract_blacklist/tools.json`（禁剥离水晶）。
6. 术式/领域类特性另挂 TechniqueHandler/DomainRegistry + BaseTechnique/BaseDomain + advancement。

### E. 新增帕秋莉手册条目
1. `assets/tinkersnewlife/patchouli_books/guide/en_us/entries/<name>.json`（**注意：手册只有 en_us 目录，内容是中文，照抄现状**）：
   抄 kai.json：name/category(`tinkersnewlife:techniques|domains|tools|...`)/icon/sortnum/可选
   advancement/pages（`patchouli:text`、`patchouli:spotlight{item,text}`、`patchouli:multiblock` 结构图）。
2. 新类目在 `categories/<cat>.json`。
3. 进度门控：`data/.../advancements/<cat>/<name>.json`（impossible 触发器）+
   `TechniqueAdvancementHandler` 静态表 `put(modifierId, "<cat>/<name>")`（每 20 tick 自动授予）。
4. 条目文本直接写条目 json（无需 lang）。

## 四、咒力核心生成仪式（快速回顾）
- 结构：格赫罗斯矿石下放焦黑/焦褐材料量器（存 ≥864mB=6 锭流体），矿石四周隔 1 格放石/铁/金/钻石块。
- 触发：空手右键 GHELOTH_ORE；5 秒后消耗流体 + 50 级经验 → 生成核心
  （材料=流体经 material_fluid 反查；咒力总量/输出 1~5；随机 1 术式 + 1 领域；30% 额外术式槽 ≤3）。
- 熔化回收：丢冶炼炉 → `auto_material_melting` 配方按 `recipes/materials/<mat>_material_fluid.json` 还原流体。
- 术式水晶获取：墨默商人每日货架随机 2 个（`ModifierCrystalItem.withModifier`）；领域靠仪式/剥离转移。

## 五、常用工具与引用速查

### 咒力（`content/curse/CursePowerHelper.java`）
- 核心查找：`findEquippedCurseCore(player)`（curios `curse_core` 槽）；`getModifierLevel(core, id)`。
- 等级/亲和：`getCurseOutputLevel(player)`（含天与咒缚 +1 / 咒种寄生 -1）、`getCurseTotalLevel`、
  `getCurseAffinity(player)`（饰品之和 + 临时 + 束缚加成 - 寄生60）。
- 数值/支付：`getMaxCurse`（总量×(输出+亲和/10)×500）、`getCurse/setCurse/addCurse/spendCurse`；
  `payCurseWithSoulFallback(player, cost)`（结界碎片 1枚=25 → 咒力 → 诡厄灵魂能量 1:3，返回 0/1/-1）；
  `countBoundaryFragments` / `consumeBoundaryFragments`。
- 状态：`isCurseInfinite` / `applyBurnout|isBurnout|getBurnoutRemainingSeconds` /
  `applySeal|isSealed|getSealedRemainingSeconds`。

### 术式（`BaseTechnique` 内置）
- `tryUse(player)` 模板：熔断检查 → 扣费 → 视线索敌(16格) → 距离校验 → `onCast`。
- `getCost` / `payCost` / `findTarget` / `isTargetInRange` / `onCast`。
- `computeBaseDamage`（共享成长伤害）、`amplifyTechniqueDamage`（模块化魔杖增幅）、`spawnSlashParticles`。
- 伤害型术式务必调用 `CurseCoreTraitHelper.applyCurseCoreTraits/afterCurseCoreHit`
  （`content/curse/CurseCoreTraitHelper.java`，手动触发核心材料特性）。

### 领域（`content/curse/domain/`）
- `BaseDomain`：`buildBarrier/removeBarrier/removeBarrierOverlap`（墙）、`spendCurse`（每秒扣费+灵魂兜底）、
  `clampEntities`（困锁，每 5 tick）、`clashOpponent/clashCostMultiplier`（对抗）、
  `getBarrierPositions`（供破域掉落碎片）；子类抽象钩子 `getDomainNameKey()` / `isValid(player)`，
  可选 `onOpen/onTick(player, serverTickCount)/onClose(player,msgKey)/onClashStart/onClashEnd`。
  **计时用 `server.getTickCount()`，勿用 getGameTime**（踩坑）。
- `DomainRegistry`：`registerDomain(id, factory)` / `toggleDomain` / `close` / `closeBySeal` /
  `breakDomainByBarrier` / `getAllDomainIds`。领域被破坏：展开 <40 tick 不掉碎片，每墙块 1/100 掉
  `ModItems.BOUNDARY_FRAGMENT`。

### 注册表入口
- 内容：`content/ModItems|ModBlocks|ModEffects|ModSounds|ModEntities|ModMenus|ModRecipeSerializers|Modifiers|ModCreativeTabs|ModFluids`（全 DeferredRegister）。
- 匠魂 modifier：`content/Modifiers.java`（`ModifierDeferredRegister` + `StaticModifier`）。
- curios 槽：`content/ModCurios.java`（IMC）+ `data/curios/tags/items/<slot>.json`。
- 网络包：`TinkersNewlife.registerPacket(C2S)` / `registerClientPacket(S2C)`。
- 生物属性：`TinkersNewlife.onRegisterEntityAttributes`；客户端渲染/按键：`client/handler/ClientEventHandler.java`。
- 匠魂 API：`ToolStack`(from/addModifier/getModifierLevel/setMaterials/rebuildStats/createStack/addSlots)、
  `SlotType.getOrCreate`、`MaterialNBT/MaterialVariant`、`ModifierRecipeLookup.addRecipeModifier/addSalvage`、
  `TinkerRecipeTypes.DATA`；工具安全读取 `util/ToolHelper.getToolStack`（IModifiable 守卫）。

### 施工铁律（踩坑记录）
1. 注册表冻结：内容一律 DeferredRegister，`new Item` 只许出现在 register supplier 内。
2. 术式/领域 trait 是"占位标记"，**逻辑写进 Technique/Domain 单例**（通过 ModifierId 关联）。
3. crystal/salvage/extract 配方与墨默商人货架**自动派生自 TechniqueHandler/DomainRegistry**，
   新增术式/领域后无需再写单个配方 json。
4. 蓄力术式注意登出/死亡/切换取消（`TechniqueHandler.onPlayerLoggedOut/onPlayerDeath` 里登记 cleanup）。
5. 网络包 C2S/S2C 方向别混；S2C 用 registerClientPacket。
6. 核心上 modifier 的增删 UI 是匠魂工匠站配方系统，不是自定义 Screen；要做专属 GUI 才需新写
   （参考 `client/screen/SilentGloveScreen` + ModMenus + 双向包模式）。
7. 帕秋莉手册只有 `en_us` 目录（内容是中文），新增条目放 en_us 即可。
8. **领域负面效果必须能被新阴流三技巧抵挡（除伏诛赐死外）**：onTick 施加定身/点燃/伤害/压力前
   一律查 `SkillHandler.isProtected(sp, this)`，命中即 `continue`。嵌合影翳庭曾漏加（做成"技巧无效"）

18. **软依赖铁律：任何编译期「直接引用」goety 类 = 无 goety 环境启动即崩**（2026-09 dev 测试环境踩坑）：

      可落脚处（`trySpawnAtFullMoon`/`spawnNearPlayer`），优先草方块上方或亮度 ≥8；
      用 `lastFullMoonSpawnDay`（worldDay）防同夜重复；生成器不再按村庄钟 POI。
    - 消失：自然刷新且未雇佣，白天到来（dayTime<13000）先触发逃离——`tickFleeDespawn`
      每 tick 朝"背离所有玩家"的合方向寻路（导航到 12 格外目标，到达后再定新目标＝多次寻路），
      10 秒（`FLEE_DESPAWN_TICKS=200`）窗口结束后 `discard`；雇佣中/到期返回续雇期内不消失。

25. **多级槽位强化（1级占槽/后续无槽）与灵魂获取增幅**（2026-09 噬魂 soul_eater 落地）：
    - 配方：`recipes/modifiers/soul_eater{,_2,_3}.json`，`tconstruct:modifier`；1 级写
      `slots.upgrades:1`（占升级槽），2/3 级不写 slots（=无槽位强化）；等级用
      `{"max":1}`→`{"min":2,"max":3}`→`{"min":3,"max":4}`（照 quantum_bag 惯例）。
    - 配方 inputs 用户要求：**每个物品一个对象、不写 amount**；数量 >1 就**重复该物品对象**
      （如"诅咒金属锭×2"= 两个 `{"item":"goety:cursed_ingot"}`）。跨 mod 物品全在诡厄：
      诅咒金属锭=`goety:cursed_ingot`、诅咒金属块=`goety:cursed_metal_block`、
      饥饿核心=`goety:hunger_core`、禁书碎片=`goety:forbidden_piece`、
      阴影石=`goety:shade_stone`、觉醒绿宝石=`goety:magic_emerald`。
    - 效果 hook（Goety 加灵魂在内部、无对外事件）：`SoulEaterHandler` 服务端每 tick 用
      `SoulEnergyBridge.getSouls` 记录增量，玩家装备（主/副手+盔甲槽，同灵魂修复候选）带
      `soul_eater` 时补发 `增量×0.25×级 + 1`；用「基线更新到补发后值」避免递归放大；
      `SoulEnergyBridge` 新增 `addSouls(Player,int)`（反射 SEActive 优先、图腾兜底）。
