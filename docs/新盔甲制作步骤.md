# 新增一套盔甲 · 完整步骤

> 适用：本模组（Forge 1.20.1 / TConstruct 3.11.2.166 / Mantle）
> 本文只列步骤与文件，不含具体数值；数值按你的设计填。

---

## 0. 先决定三件事（决定后面要写多少文件）

| 选择 | 说明 | 工作量 |
|---|---|---|
| **A. 材质**：新材质 / 复用已有材质 | 复用（如现有 `durandal`）可跳过第 1 节全部 | 新材质 +5 个文件 |
| **B. 写法**：**古代式** / 部件式 | 古代式＝只写 `material_stats`，无部件物品；部件式＝匠魂板甲那种「铠甲板 + 锁甲」两块，可在工匠站拼装 | 古代式省一半文件 |
| **C. 获得方式**：转化 / 合成 / 掉落 / 浇铸 | 古代式不能工匠站拼装，必须给一条获得途径 | — |

**建议第一套走「古代式」**：文件少、坑少，和我们刚改的杜兰达尔剑 / 噤默手套同一条路。
（古代工具写法见备忘录 200 条：`material_stats` 的 `stat_types` 条数 = 材料槽位数。）

## 1. 材质侧（仅新材质需要；复用材质跳过）

| 文件 | 内容 |
|---|---|
| `data/tinkersnewlife/tinkering/materials/definition/<mat>.json` | `tier` / `craftable` / `hidden` |
| `data/tinkersnewlife/tinkering/materials/stats/<mat>.json` | **至少要写 4 个护甲统计**：`tconstruct:plating_helmet` / `plating_chestplate` / `plating_leggings` / `plating_boots`（各含 `durability` 与护甲值字段）；要更还原匠魂板甲再加 `tconstruct:maille` |
| `data/tinkersnewlife/tinkering/materials/traits/<mat>.json` | 材质特性（可空数组） |
| `data/tinkersnewlife/tinkering/materials/generator/<mat>.json` | 材质**调色板** + `supported_stats` —— **必须包含 `plating_*`**，否则这套材质的盔甲贴图生成不出来（会是一片紫黑） |
| `data/tinkersnewlife/tinkering/materials/render/<mat>.json`（可选） | 金属/木质等渲染分类 |

流体（想让盔甲能熔炼/浇铸才需要）：
`content/ModFluids.java` + `mantle/fluid_texture/<mat>.json` + `recipes/smeltery/melting/...` + `recipes/materials/<mat>_material_fluid.json`
（流体贴图记得：**still 16 宽、flowing 32 宽**，见备忘录 197。）

## 2. 盔甲工具定义 ×4

**命名规则（关键）**：Java 侧 `ModifiableArmorMaterial.create(id, 音效)` 会自动生成 4 个工具定义，
id 分别是 **`<id>_helmet` / `<id>_chestplate` / `<id>_leggings` / `<id>_boots`**。
所以 datapack 文件名必须与之一一对应：

```
data/tinkersnewlife/tinkering/tool_definitions/<id>_helmet.json
data/tinkersnewlife/tinkering/tool_definitions/<id>_chestplate.json
data/tinkersnewlife/tinkering/tool_definitions/<id>_leggings.json
data/tinkersnewlife/tinkering/tool_definitions/<id>_boots.json
```

**古代式内容示例**（四份只有 `stat_types` 不同）：

```json
{
  "modules": [
    {
      "type": "tconstruct:material_stats",
      "primary_part": 0,
      "stat_types": [ "tconstruct:plating_helmet" ]
    },
    {
      "type": "tconstruct:default_materials",
      "materials": [ { "type": "tconstruct:random", "tier": 3 } ]
    },
    { "type": "tconstruct:modifier_slots", "slots": { "defense": 3, "upgrades": 2 } },
    { "type": "tconstruct:traits", "traits": [ { "level": 1, "name": "tinkersnewlife:<trait>" } ] }
  ]
}
```

- 四格的 `stat_types` 依次换成 `plating_chestplate` / `plating_leggings` / `plating_boots`。
- **部件式**则把第一个模块换成 `part_stats`，`parts` 顺序为 `[plating 部件, maille 部件]`，并按匠魂板甲追加
  `{ "type": "tconstruct:fixed_material_name", "index": 0 }`。

## 3. Java 侧（`content/ModItems.java`）

```java
/** 盔甲材质：一次生成 4 个槽的工具定义（<id>_helmet / _chestplate / _leggings / _boots） */
public static final ModifiableArmorMaterial STAR_ARMOR =
        ModifiableArmorMaterial.create(new ResourceLocation(TinkersNewlife.MOD_ID, "star_armor"),
                SoundEvents.ARMOR_EQUIP_NETHERITE);

public static final RegistryObject<ModifiableArmorItem> STAR_HELMET =
        ITEMS.register("star_helmet",
                () -> new ModifiableArmorItem(STAR_ARMOR, ArmorItem.Type.HELMET, new Item.Properties()));
// 同法注册 STAR_CHESTPLATE / STAR_LEGGINGS / STAR_BOOTS
```

- `ModifiableArmorItem` = 匠魂的可改造盔甲（`extends ArmorItem`，走匠魂的耐久/强化体系）。
- 物品注册名（`star_helmet`）与工具定义 id（`star_armor_helmet`）**可以不同名**，但建议成套命名，别搞混。

## 4. 资源侧（`assets/tinkersnewlife/`）

| 内容 | 路径 |
|---|---|
| 物品模型 ×4（正常） | `models/item/<item>.json` |
| 物品模型 ×4（破损态） | `models/item/<item>_broken.json` |
| 部件底图（灰阶 sprite，材质调色板在其上着色） | `textures/item/tool/armor/<set>/<slot>/plating.png`、`maille.png` |
| 穿在身上的贴图 | `textures/tinker_armor/...`（匠魂盔甲层） |
| 材质自动生成登记 | `tinkering/generator_part_textures.json` 追加每条的 `path` + `stat_type` |

物品模型（照匠魂板甲的写法）：

```json
{
  "loader": "tconstruct:tool",
  "parent": "forge:item/default",
  "textures": {
    "plating": "tinkersnewlife:item/tool/armor/star_armor/helmet/plating",
    "maille":  "tinkersnewlife:item/tool/armor/star_armor/helmet/maille"
  },
  "parts": [
    { "name": "plating", "index": 0 },
    { "name": "maille",  "index": 1 }
  ]
}
```

`generator_part_textures.json` 追加：

```json
{ "path": "tinkersnewlife:item/tool/armor/star_armor/helmet/plating", "stat_type": "tconstruct:plating_helmet" }
```

语言（`lang/zh_cn.json` + `en_us.json`）：4 条物品名 +（新材质时）材质名、特性名/描述。

## 5. 标签侧（给匠魂的标签要写在 `data/tconstruct/` 下）

| 文件 | 作用 |
|---|---|
| `data/tconstruct/tags/items/modifiable/armor.json` | 声明"这是可改造盔甲" |
| `data/tconstruct/tags/items/modifiable/armor/helmets.json` | 头盔（本模组的「闭耳塞听」就是按这个标签判断的） |
| `.../armor/chestplate.json`、`leggings.json`、`boots.json` | 其余三格 |
| `.../modifiable/durability.json`、`bonus_slots.json`（可选） | 有耐久 / 有额外强化槽时加上 |
| `data/tinkersnewlife/recipes/smeltery/melting/...`（可选） | 想熔掉回收就写 |

写法（`replace: false` 追加，别覆盖本体的）：

```json
{ "replace": false, "values": [ "tinkersnewlife:star_helmet" ] }
```

## 6. 创造栏

`content/ModCreativeTabs.java` 里四格各加一行：

```java
addAllToolVariants(output, STAR_ARMOR.getArmorDefinition(ArmorItem.Type.HELMET), ModItems.STAR_HELMET.get());
```

该辅助方法会把本模组所有材质各生成一个变体（不可用材质自动跳过；与匠魂本体逻辑一致）。

## 7. 构建与验证

```powershell
cmd /c ".\gradlew build --console=plain > build\cb.txt 2>&1"      # 看 BUILD SUCCESSFUL
powershell -ExecutionPolicy Bypass -File tools\deploy.ps1          # 会拒绝在游戏运行时部署
```

进游戏（`gradlew runClient`）看日志与实物，重点查：

1. 有没有 `Failed to parse tool definition` / `Unknown stat type` / `Missing tool definition`；
2. 有没有 **`has fewer tool parts than default materials`** —— 这条说明 `stat_types` 条数少了（会丢材料）；
3. 创造栏能拿到 4 件 → 穿上 → 看护甲值、材质名、防御强化槽；
4. 贴图有没有缺（缺贴图会显示成紫黑格 / 空白）；
5. 破损外观、熔炼回收是否正常。

## 8. 常见坑（本模组已经踩过的）

- **`stat_types` 条数必须和 `default_materials` 条数对齐**，也要和生成代码里 `MaterialNBT.of(...)` 的参数个数对齐 —— 否则匠魂报错并**静默丢掉后面的材料**（噤默手套就是这么只显示头部件材料的）。
- 模型 `parts` 的 `index` 必须与 `material_stats` 的 `stat_types` **顺序一致**，否则贴图错位/串材质。
- 材质 `generator` 的 `supported_stats` 必须含 `plating_*`，不然盔甲贴图生成不出来。
- 给匠魂的标签写在 `data/tconstruct/...`，自己的写在 `data/tinkersnewlife/...`；`replace` 一律 `false`。
- ASCII 像素图 / 手写数据落盘前先做长度自检（备忘录 198 的教训）。
- PowerShell 的**变量名与哈希表键都不区分大小写**（`'H'`/`'h'` 会冲突）。
