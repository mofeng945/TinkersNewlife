## 0. 先分清两件事（很容易混）

| 名字 | 入口 | 管什么 | 手法 |
|---|---|---|---|
| **穿甲** | 西洋剑（`RapierItem`） | **只无视"护甲"那一段** | ⭐ 事件层**补偿**（不加伤害类型 ✗） |
| **穿透 / 真伤** | `TruePierce.apply(...)` | **整条 `hurt()` 管线 + 事件层改数值** | ⭐ 真伤源 + 分块连打 + 差额直补 |

⚠ 两者**互不隶属**：穿甲是"在护甲那一段加回去"，穿透是"用特殊伤害源重打"。

---

## A. 穿甲（西洋剑）全流程

### A1. 为什么不用伤害类型
1.20.1 的"无视护甲"是**伤害类型标签** `minecraft:bypasses_armor` 驱动的 ⇒ 给武器换伤害类型会**波及所有用该类型的攻击**（整合包里别的模组也吃这套）⇒ 用户口径选**方案 B**：只在"护甲这一段"做补偿，影响面最小。

### A2. 依赖的原版事件顺序（1.20.1 实查）
```
LivingEntity#hurt(...)
  amount = ForgeHooks.onLivingHurt(this, source, amount);   ← LivingHurtEvent   【护甲前】
  amount = applyArmorCalculations(source, amount);           ← 护甲在这里被减掉
  amount = applyPotionDamageCalculations(source, amount);    ← 抗性提升 / 保护附魔
  f1     = ForgeHooks.onLivingDamage(this, source, amount);  ← LivingDamageEvent 【护甲后 + 药水后】
```

### A3. 流程
```
① LivingHurtEvent（护甲【前】）
   ├─ 客户端 ⇒ 结束
   ├─ rapierAttack(source, victim) 不成立 ⇒ 结束
   │    判据：source.getEntity() 是 Player ✓ 且 player != victim ✓
   │          且 player.getMainHandItem() 是 RapierItem ✓
   └─ 记 { victim.UUID → [gameTime, 护甲前伤害] }
        ⚠ 带上 gameTime ⇒ 跨 tick 的陈旧记录自动作废
② LivingDamageEvent（护甲【后】）
   ├─ 取出并删除记录；没有记录 ⇒ 结束
   ├─ 记录里的 gameTime ≠ 当前 gameTime ⇒ 结束（那次伤害被取消/免疫了）
   ├─ rapierAttack 不成立 ⇒ 结束
   ├─ source 本来就带 bypasses_armor ⇒ 结束（⭐ 别重复加）
   ├─ victim.getArmorValue() ≤ 0 或 护甲前伤害 ≤ 0 ⇒ 结束
   └─ absorbed = 护甲前伤害 − CombatRules.getDamageAfterAbsorb(护甲前伤害, 护甲, 韧性)
        ⭐ 用**原版同一条公式**算出"护甲本来要吃掉多少"
      event.setAmount(当前值 + absorbed)     ← 把它加回去
```
### A4. 边界
- ✅ 只穿**护甲**：抗性提升 / 保护附魔那部分**保留**（它们在上面的第二步，我们没动）；
- ✅ 只对**主手拿西洋剑的玩家攻击**生效，其它来源一概不动；
- ✅ 不额外排除创造模式（创造玩家打出的伤害本来就该正常生效）。

### A5. 附带：手持西洋剑时**副手盾牌无法使用**
```
ShieldBlockEvent
  ├─ 非玩家 ⇒ 结束
  ├─ 主手不是 RapierItem ⇒ 结束
  └─ setCanceled(true) + setShieldTakesDamage(false)      ← 完全不格挡 ✓
```
原因：右键后跳已经吃掉右键 ⇒ 绝大多数情况下盾牌起不来 ⇒ 但**潜行时故意放行**右键（留给放置/交互）⇒ 用这个事件把那条缝堵上。

## B. 穿透 / 真伤（TruePierce）全流程

## B0. 触发（三个入口，全部汇入 `TruePierce.apply`）

```
入口① 穿透 EX（修饰符 ex_pierce）
   ├─ 玩家近战：AttackEntityEvent
   │    ├─ 客户端 / 目标解析失败 ⇒ 结束
   │    ├─ 主手工具 getActiveModifierLevel(ex_pierce) ≤ 0 ⇒ 结束
   │    ├─ event.setCanceled(true)                 ← 取消原版伤害
   │    └─ damage = player.getAttributeValue(ATTACK_DAMAGE)
   │         ⇒ TruePierce.apply(player, 目标, damage)
   └─ 投射物命中：ProjectileImpactEvent
        ├─ 必须是 AbstractArrow ✓ 命中实体 ✓
        ├─ 射手是玩家 ⇒ 用 ProjectileWeaponHelper.getProjectileWeapon(箭, 玩家) 取武器
        │  射手非玩家（仆从）⇒ 用 shooter.getMainHandItem()（goety 仆从 AI 用主手匠魂弓）
        ├─ 武器无 ex_pierce ⇒ 结束
        ├─ event.setCanceled(true) ＋ projectile.discard()   ← 移除箭，避免二次命中
        └─ damage = arrow.getBaseDamage()（≤0 时取 1）
             ⇒ TruePierce.apply(shooter, 目标, damage)

入口② 天逆鉾（TianNiHuoItem）
   └─ AttackEntityEvent：主手是天逆鉾 ⇒ 对所有目标都走穿透
        ⚠ 历史：以前只放行"诡厄受限 Boss / 凋灵"，打普通生物会 return ⇒ 退化成普通攻击
          ⇒ 戴着命灯指轮时被慈悲锁在 1 点血（玩家实测）⇒ 现已对所有目标生效
        ① event.setCanceled(true) + player.swing(MAIN_HAND)
        ② dmg = getAttributeValue(ATTACK_DAMAGE)
             + 若 CognitiveMaskItem.treatedAsUndead(player, 目标) ⇒ +6（凋灵是亡灵）
        ③ 前置：notifyHiredMomo（告知雇佣的墨默集火）
                 bypassWitherInvuln（凋灵：invulnerableTime=0 + 反射清零出生无敌 + setInvulnerable(false)）
                 读 obsidianInvul ⇒ >0 则 shatterProtectingPillars（天逆鉾直接碎保护柱）
        ④ TruePierce.apply(player, 目标, dmg)
        ⑤ 柱没碎且目标还活着 ⇒ 还原保护计时
        ⑥ 反馈粒子（CRIT）+ 音效（PLAYER_ATTACK_CRIT）
        ⚠ 任何异常 ⇒ **撤销取消**、回退原版攻击（绝不"攻击即崩溃"），首次异常记一次日志

入口③ 墨默的挥击（MomoMerchant）
   └─ TruePierce.apply(this, target, dmg)      ← 与上面同一套
```

### B0.5 目标解析（多段 Boss）
`resolveTarget(被击中实体)`：命中 `LivingEntity` 直接用；命中 `PartEntity` 则**解析回主实体**（灾变利维坦这类多段 Boss 的受击实体是 PartEntity，其 `hurt` 只转发到主实体）⇒ 必须打主实体，主实体 `hurt()` 内的无敌/限伤判断才吃得到 bypass 标签。

## B1. `apply()` 的前置（**在真正打之前**）

```
① 参数与状态
   target 为空 / damage ≤ 0 / 客户端 / 已移除 ⇒ 结束
② 同心戒互免
   TwinRingLink.arePaired(attacker, target) 成立 ⇒ 结束
   ⚠ 必须挡在这里：本方法是"差额直接 setHealth 补齐"的，LivingAttackEvent 拦不住它
③ 咒力伤害记账
   CurseDeath.mark(target)            ← 死亡信息统一成"被诅咒致死"
④ 击杀归属预记
   KillAttribution.remember(target, attacker)   ← 死亡时按最后一击回溯归属
⑤ ⭐ 归属直写目标（不依赖任何事件）
   攻击者是玩家 ⇒ target.setLastHurtByPlayer(pierceOwner);
                  target.setLastHurtMob(pierceOwner);
   ⚠ 起因（用户实测）：命灯指轮 + 带穿透的法杖打怪**什么都不掉** ✗
     命灯的慈悲会截致死伤害但**特意豁免穿透** ⇒ 这一击成了收尾一击；
     而收尾段常常是**无主源**（第③条分支甚至直接 setHealth + die()，**根本不经过事件**）
     ⇒ lastHurtByPlayer 永远空 ⇒ 战利品表 killed_by_player 不成立 ⇒ 一件不掉
     ⇒ 于是直接写进目标本身，三条分支全覆盖
⑥ ⓪ 绝对防御穿透（见 B2）—— begin，包住整个打击，finally 里 end
```

---

## B2. ⓪ 绝对防御穿透（`AbsoluteDefense`）

```
背景：潘多拉之咒·现实压制 在 LivingAttackEvent 里直接 setCanceled(true)
      ⇒ 伤害事件根本不发生 ⇒ 伤害标签与"事件层顶开"**都够不着**
判据：攻击者的【现实指数】属性 ≥ 词条等级 才放行（词条等级上限 7）
后门：官方留的就是这个属性 ⇒ 把攻击者的现实指数**临时抬到远高于上限** ✓
流程：begin(attacker)
        ├─ 取得攻击者的"现实指数"属性实例（按注册名查，模组不在场返回 null）
        ├─ 加一个临时修饰符把值抬过阈值 ⇒ 返回 true（表示"我们动过手，要还原"）
        └─ 失败 ⇒ 返回 false
      noteSunblockTarget(target)
      try   { 进入 B3…B7 }
      finally { 动过手 ⇒ end(attacker) 摘掉临时修饰符 }
```

## B3. ② 禁疗 + 清掉自家限幅

```
suppressRegen(target)        ← GoetyBridge.suppressApostleRegen（否则再生把伤害吃回去）
clearOwnDamageLimit(target)  ← 移除本模组 DAMAGE_LIMIT 效果（它会把多段伤害整段取消）
```

## B4. ③ 下界亚波伦（`hurt()` 管线被免疫窗整个取消）

```
GoetyBridge.isNetherApollyon(target) 成立
  ⇒ directDamage(target, want, 带攻击者的源)
       hp = 当前血 − want
       hp ≤ 0 ⇒ setHealth(0) ；若未 removed ⇒ die(源)
       否则   ⇒ setHealth(hp)
  ⇒ 直接结束（不再走分块连打）
```

---

## B5. ④ 分块连打

```
startHp  = 目标当前血
dealt    = chunkedHurt(目标, 带攻击者的源, want)
             while 还有余量 && 目标存活 && 未移除 && 段数 < 64:
                 part = min(余量, 19)
                 target.invulnerableTime = 0        ← 清无敌帧
                 markIntent(目标, part)             ← 登记"这一段想打多少"
                 target.hurt(源, part)
                 余量 -= part
             返回 startHp − 目标当前血（＝真实打掉多少）

⚠ 若 dealt ≤ 0.01 且目标还活着  ⇒ 换【无主源】再打一遍
   （针对 Mowzie 钢铁守护者那类"有攻击者即免疫"的目标）
```

### 事件层顶开（每段都会走）
```
markIntent(目标, part)
  ⇒ INTENT[目标UUID] = (part, 当前 gameTime)

LivingHurtEvent   @LOWEST  ┐
LivingDamageEvent @LOWEST  ┘ → force(target, source, setAmount)
     ├─ INTENT.remove(目标UUID)，没有 ⇒ 结束
     ├─ 记录的 gameTime ≠ 当前 gameTime ⇒ 结束（防串到别的打击）
     ├─ source 不是"真伤类" ⇒ 结束（见下）
     └─ setAmount(登记值)      ← 在最后一刻把数值按原意放回去
```
**"真伤类"判据**：本模组 `tinkersnewlife:true_pierce` **或**任何带 `bypasses_invulnerability` 的源（含 Goety 那支）。

**为什么要这一层**：别的 mod 会在 `LivingHurtEvent`/`LivingDamageEvent` 里改数值（akaishi 把监守者单次受击压到 24；启示录给亚波伦加单次 20 上限）—— 标签对这些**完全无用**。

## B6. ⑤ 差额直补

```
shortfall = want − max(dealt, 0)
shortfall ≤ 0.01 ⇒ 结束
目标已死 / 已移除 ⇒ 结束

hp = 目标当前血 − shortfall
hp ≤ 0 ⇒ setHealth(0)；若未 removed ⇒ target.die(带攻击者的源)
         ⚠ 历史坑：setHealth(0) 之后 isAlive() 恒为 false ⇒ 原来那句 die() 永远不执行
           ⇒ 怪停在 0 血：不掉落、不给经验、无死亡事件 ⇒ 现已补上
否则   ⇒ setHealth(hp)

⭐ 低血"受击回满"免伤的处决兜底（启示录使徒那类）：
   是 Goety 使徒 && 还活着 && 血 ≤ 18% 上限 && (startHp − 当前血) < 5
     ⇒ setHealth(0) + die()
```

## B7. 告知（`PierceAware`）

```
target 实现了 PierceAware
  ⇒ 若（真的掉血了 或 目标正死亡）
        aware.onTruePierce(damage, source(level, attacker))
  ⚠ 免疫时不通知（不该有受击音效/记账）
用途：补"因为不经过 hurt() 而拿不到的反馈/记账"
      例：墨默（一击必杀判定用 lastDamageTaken、受击语音在 hurt() 里播）
```

## C. 关键常量 / 数据

| 项 | 值 | 说明 |
|---|---|---|
| 单段上限 `CHUNK` | **19.0** | 故意低于常见的"单次限伤"阈值，保证每段都能落地 |
| 段数上限 `MAX_CHUNKS` | **64** | 19 × 64 ≈ 1200 点 |
| `INTENT` 防串键 | UUID + **gameTime** | 只认"刚刚那一击" |
| 真伤源优先级 | ① Goety 那支（部分 Boss 认它）② `tinkersnewlife:true_pierce` | 两者都带 `bypasses_invulnerability` |
| `true_pierce` 定义 | `message_id: tinkersnewlife.truePierce`／`exhaustion: 0.0`／`scaling: never` | |
| 它挂的标签 | `bypasses_armor`／`cooldown`／`effects`／`enchantments`／`invulnerability`／`resistance`／`shield`（7 个）＋ 自家的 `ignores_mana_shield` | |

## D. 与其它系统的交叉点

| 系统 | 关系 |
|---|---|
| **命灯指轮** | 穿透是**真伤**，**特意豁免**命灯的"慈悲留 1 血"（命灯那边也早退放行，两端一致、与事件顺序无关）⇒ 带穿透的近战/投射物可照常杀死目标 |
| **同心戒** | 互为同伴的两名玩家互相免疫 ⇒ 穿透也不例外，挡在 `apply` 入口 |
| **咒力伤害记账** | `CurseDeath.mark` ⇒ 死亡信息统一成"被诅咒致死" |
| **击杀归属** | `KillAttribution.remember` + `setLastHurtByPlayer/Mob` ⇒ 解决"用穿透打怪什么都不掉" |
| **自家伤害限幅** | 分块前**主动清掉**（否则多段伤害被整段取消） |

## E. 一句话总览

```
触发（穿透EX / 天逆鉾 / 墨默）
  ⇒ 解析到主实体
  ⇒ 前置（同心戒互免 / 记账 / 归属直写 / 绝对防御临时开锁）
  ⇒ 禁疗 + 清自家限幅
  ⇒ 是下界亚波伦？ ──是→ setHealth 直伤 + die()
                    └─否→ 分块连打（每段 ≤19、≤64 段、每段登记意图）
                            ├─ 打不动 ⇒ 换无主源再打一遍
                            └─ 每段在 LOWEST 优先级把数值顶回登记值
  ⇒ 差额直补（吃掉的部分按血量差补上；致死补 die()；使徒低血走处决兜底）
  ⇒ 告知 PierceAware
```
